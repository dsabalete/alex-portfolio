# Design

## Context

The `useSEO` hook in `src/hooks/useSEO.ts` already manages most head metadata by creating/updating meta tags in `document.head` with in-place updates (the `setMetaContent` helper). However, JSON-LD is generated by `generateAllSchemas` in `src/lib/structuredData.ts`, which currently returns full `<script type="application/ld+json">...</script>` HTML strings assigned to `mainScript` and `fallback`, then rendered as JSX children (`{mainScript}`) in `HomePage.tsx`, `AboutPage.tsx`, `ContactePage.tsx`, and `NotFoundPage.tsx`. React renders string children as escaped text, so the JSON-LD is visible on the page and not parsed as structured data.

## Goals / Non-Goals

**Goals:**
- JSON-LD `<script type="application/ld+json">` blocks are injected into `document.head`, invisible to users and parseable by search engines.
- JSON-LD scripts are managed with in-place updates (no duplicates) across navigations, consistent with other head tags.
- Minimal disruption to existing SEO hook patterns and the `structuredData.ts` generator API.

**Non-Goals:**
- Changing which schema types are emitted or restructuring the schema data model in `structuredData.ts`.
- Switching to a React head-management library (e.g., `react-helmet`).
- Altering OG/Twitter meta tag handling.

## Decisions

1. **Refactor `generateAllSchemas` to return parsed JSON objects** instead of pre-wrapped `<script>` HTML strings. The function will return an array of plain schema objects (or `{ main, fallback }` objects with parsed JSON), so callers can serialize and inject them. Rationale: keeps `structuredData.ts` focused on data, lets the injection layer handle serialization and DOM concerns. This keeps the change minimal — only the return shape changes; the schema content is unchanged.

2. **Add JSON-LD injection to `useSEO`** via a new `seoJsonLd` option (array of schema objects). The hook serializes each object with `JSON.stringify` and injects/updates `<script type="application/ld+json">` tags in `document.head` using a `data-ldjson` marker attribute for in-place updates. Rationale: co-locates all head management in one place, reuses the existing in-place update pattern, and ensures JSON-LD is cleaned up/updated on navigation.

3. **Remove `{mainScript}` / `{fallback}` JSX children** from all page components and instead pass the schema objects to `useSEO`. Rationale: the simplest way to stop the visible-text rendering is to remove those children; the hook now owns head injection.

### Alternatives Considered

- **Use `dangerouslySetInnerHTML`** to render the `<script>` strings as JSX inside a `<script>` element in body. Rejected: `document.body` script injection is not valid for JSON-LD consumption by crawlers in all contexts, and it still pollutes body content. The spec requires head injection.
- **Introduce `react-helmet` or `@pi-helmet/react`.** Rejected: adds a new dependency for a narrow concern; the existing hook-based approach is sufficient and consistent with the project's minimal-stack philosophy.

## Risks / Trade-offs

- **[Risk]** Changing `generateAllSchemas` return shape could break other callers. → **Mitigation**: Only the four page components call it; all are updated in the same change. No tests import `generateAllSchemas` directly (verified via grep).
- **[Risk]** Stale JSON-LD scripts accumulating across rapid navigations. → **Mitigation**: The hook uses an updatable marker attribute and replaces content in place; on route change the previous route's scripts are removed before new ones are set if the set changes.
- **[Trade-off]** JSON-LD is now generated at render time inside the hook effect rather than statically at module scope. → **Mitigation**: The dataset is small (a handful of schema objects); this has no measurable performance impact.

## Migration Plan

No deployment-time migration: the structured data is generated client-side and injected at runtime. Old cached HTML renders (if any from a previous build) will simply no longer include the visible text. No user-facing data migration is required.
